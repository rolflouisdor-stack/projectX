## ✅ DONE TODAY: amounts are consistent + un-rounded everywhere

**The problem (as reported):** a scrub that netted us $0.51 was charged $0.83,
but the "payment received" email said $0.51 and the UI said $1. A later test
charged $11.92 but the UI said $12. Two distinct bugs:

1. **Surfaces showed different fields.** Checkout grossed `price_cents` up to the
   real charge (incl. the 2.9%+30¢ card fee); the email + Job History + dashboard
   showed the pre-fee `price_cents`.
2. **The UI rounded money to whole dollars.** `fmtMoney` used
   `maximumFractionDigits: 0`, so $0.83 → "$1" and $11.92 → "$12". Server/DB/email
   values were correct the whole time — only the display rounded.

**What shipped (3 commits, all live):**

- **`5e23f27`** — Persist the real charge on scrub jobs + fix the email.
  - New column **`scrub_jobs.amount_paid_cents`** = the exact card charge
    (`add_processing_fee(price_cents).total_cents`), set at pay time in
    `pay_scrub_job` (covers both the Stripe and stub paths — it's computed before
    the branch). Boot migration adds it idempotently.
  - `notify_eo_payment_received` now prints **`Amount paid: $X.XX`** from the
    stored charge. Helper `email_service._amount_paid_cents(job)` falls back to
    recomputing via `add_processing_fee` for jobs paid before the column existed.
- **`6453df5`** — Make Job History + dashboard show the charged total.
  - New shared helper **`pricing.effective_total_cents(price_cents,
    amount_paid_cents)`**: returns the exact stored charge for paid jobs, else the
    grossed-up total for unpaid quotes. The single number every customer-facing
    surface should use — never the pre-fee `price_cents`.
  - Both `ScrubJob.to_dict()` and `PurchaseJob.to_dict()` now expose
    **`amount_paid_cents`** + **`amount_total_cents`** / `amount_total_dollars`.
  - `jobs.html` renders `amount_total_cents`; `dashboard_summary` uses
    `effective_total_cents` for the recent rows + `total_spent_cents`.
  - **Purchases mirrored:** added `purchase_jobs.amount_paid_cents` (+ migration)
    and set it in `pay_purchase_job`, so the buy flow is consistent too.
- **`ffc33a1`** — `fmtMoney` (in `_base.html`) now formats currency with
  **2 decimals** (`minimumFractionDigits: 2, maximumFractionDigits: 2`). App-wide:
  checkout, Job History, dashboard, buy quotes. `$11.92`, `$0.83`, `$1,760.00`.

**Verified against prod:** job 12 = 21,458 records × $0.000525 = **$11.27 base** →
grossed up to **$11.92** (`amount_paid_cents=1192`), exactly the Stripe charge.
Stripe's "net $0.51" on the earlier job = the $0.83 gross minus their real ~$0.32
fee. Migration columns confirmed present on both `scrub_jobs` and `purchase_jobs`.
