## Email verification flow (NEW onboarding behavior)
- Signup creates an **unverified** account and returns a **generic** message (same whether or not the email
  exists → no enumeration). **No auto-login.**
- `GET /verify?token=` activates + auto-logs-in (single-use token, 24h TTL). Bad/expired/used →
  `/login?verify=invalid|expired|already`.
- Login `403`s while unverified; the login page offers a one-click **resend**. `POST /api/auth/resend-verification`.
- **Existing users were grandfathered verified** at migration time (`mailer_users.email_verified` ADD COLUMN
  DEFAULT 1) — nobody got locked out (verified live).
- ⚠️ **Email is now load-bearing for onboarding.** If `EMAIL_ENABLED` is ever turned off, new signups can't
  verify. (Mandrill is live; `EMAIL_ENABLED=true` in prod.)

## Schema changes
